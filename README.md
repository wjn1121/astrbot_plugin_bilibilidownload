## ⚡ 快速开始

1. **安装插件**：在 AstrBot WebUI 插件市场中搜索「B站视频下载」一键安装，或手动放入 `data/plugins/astrbot_plugin_bilibilidownload/`
2. **安装依赖**：WebUI → 插件管理 → B站视频下载 → 点击「安装依赖」按钮（`aiohttp`，AstrBot 本体通常已自带）
3. **打开面板（可选）**：WebUI → 插件管理 → 找到「B站视频下载」→ 点插件卡片上的**面板/页面入口**（`views: panel`）。面板左栏按平台拆开：**概览 / 哔哩哔哩 / 抖音 / 小红书 / 试解析 / 最近 / 缓存**七个页签
4. **直接使用**：在群里丢一条链接（B 站 / 小红书 / 抖音都行），机器人回复一张图片卡片（解析信息 + AI 总结）；图文笔记会把图一起发出来

```
群友: https://www.bilibili.com/video/BV1dwYE68ED2
Bot:  [给这条消息贴了个表情，表示「开始解析」]
Bot:  📺 倒霉糯：吃饭的路如此艰难吗？
      👤 玖梦sky丶 · 2分11秒 · 12.8万播放

      📝 AI 总结（基于简介与热评）
      这是 UP 主「倒霉糯」系列的日常向短片……

      🔗 下载页：https://www.ebilibili.com/video/BV1dwYE68ED2
      💡 回复「下载」或发送 /bdl 可获取视频文件
群友: 下载
Bot:  ⬇️ 正在下载《倒霉糯：吃饭的路如此艰难吗？》…
Bot:  📺 倒霉糯：吃饭的路如此艰难吗？
      👤 玖梦sky丶 · 2分11秒 · 12.8万播放

      🎬 视频文件已附在下方
Bot:  [视频]
```

> 🖼️ 上例是**纯文本样式**。默认会渲染成**图片卡片**（UP 主头像 + 昵称 + 发布时间 → 标题 → 封面 → AI 总结）；关闭「以图片卡片回复」或渲染失败时，才会退回上面的纯文本。
>
> 📕 小红书 / 抖音同理：丢一条分享链接（连口令一起粘也行），解析完发卡片；图文笔记会把图集一起发出来，默认最多 5 张，末尾注明「这组共 N 张」。

### 🖥️ Web 面板怎么用

入口：**AstrBot WebUI → 插件管理 → 「B站视频下载」→ 面板/页面按钮**。

左栏按平台拆开，进哪个平台就改那个平台自己的东西：

| 页签 | 能做什么 |
|---|---|
| **概览** | 版本与运行时长、解析/下载/卡片计数、卡片渲染熔断状态、平台一览（可点进各平台页）、下载站三条路径近况、最近一次错误 |
| **哔哩哔哩** | **扫码登录**（手机扫一下自动写入 SESSDATA）、检测登录态、退出登录、手动填 SESSDATA；以及自动发视频、体积上限、卡片外观、热评条数、AI 总结、字幕等**可调项** |
| **抖音** | 第三方解析接口地址（可测试连通性）+ 调整项；页面上也写清了抖音为什么时好时坏 |
| **小红书** | Cookie（提高需登录笔记的成功率；点「测试」会直接告诉你**登的是谁**）+ 图集开关与张数上限 |
| **试解析** | 粘一条链接或整段分享口令 → 元信息 + **真正会发出去的那张卡片图片** + AI 总结 + 能否拿到直链。**不发群、不占去重窗口** |
| **最近** | 最近 50 条解析记录（时间 / 平台 / 标题 / 耗时 / 结果），可按平台过滤 |
| **缓存** | 各平台缓存条数与命中率，一键清空（图形版 `/bdlclear`） |

#### 关于「面板里改设置」

面板能改的项会写进插件数据目录的 `runtime.json`，**不写 AstrBot 的配置文件**：

- 每项都标着来源「面板 / 配置」，点该项的「恢复」即删掉这条覆盖、退回配置值
- 优先级：**面板覆盖 > AstrBot 配置**。原生配置面板照常可用，不会被面板改乱
- 卸载插件时删掉 `data/plugin_data/astrbot_plugin_bilibilidownload/` 即可全部复原

#### 关于扫码登录

用的是 B 站 Web 端自己的二维码接口，**不经过任何第三方**。扫码确认后插件会先拿这个
Cookie 请求一次 `nav` 接口校验，**校验通过才写入**——所以不会出现「扫了个失效的码，
把原来还能用的登录态顶掉」这种情况。二维码约 3 分钟有效，过期重新点一次即可。

## ✨ 功能特性

- 🌐 **多平台**：B 站（视频/分P/字幕）、小红书（图文与视频）、抖音（分享页解析 + 第三方接口兜底）；平台可单独启停，顺序可调
- 🖼️ **图集自动下载 + 去水印**：抖音/小红书的图文笔记会先下载到本地再发（避免防盗链导致裂图）；小红书的图用 `fileId` 直连原图 CDN，拿到的是**无水印原图**（页面给的 `!h5_1080jpg` 正中压着水印）；**默认只下前 5 张**并注明「这组共 N 张」；数量在面板「图集最多发送」里可热改（1~35 张，改完即时生效、不用重启）
- 🏷️ **卡片角标跟随来源**：B 站 / 抖音 / 小红书的卡片各用各自标识，不会把抖音内容标成 bilibili
- 🖥️ **Web 面板**：左栏按平台拆开（概览 / 哔哩哔哩 / 抖音 / 小红书 / 试解析 / 最近 / 缓存）；**试解析会把真正要发出的卡片渲染出来给你看**，且不会发到群里
- 📱 **B 站扫码登录**：面板里点一下、手机扫一下就把 SESSDATA 存好（先校验再落盘），不用再去浏览器翻 Cookie
- 🔑 **平台凭据**：面板里可填 B 站 SESSDATA、小红书 Cookie、抖音第三方接口，并能当场测试是否有效；凭据单独存文件（权限 600），不进配置、不进日志
- 🎛️ **面板可调**：体积上限、热评条数、卡片宽度、AI 总结、字幕、图集上限都在面板里改，写入 `runtime.json` 覆盖层，不动 AstrBot 配置文件
- 🖼️ **图片卡片**：解析信息 + AI 总结渲染成一张卡片（标题 / UP主头像与发布时间 / 封面 / 总结），默认开启；走 AstrBot 内置文转图，**不新增依赖、不内建字体**，渲染失败自动退回纯文本
- 🔗 **链接自动识别**，无需唤醒词，整段分享文本直接粘也能认：
  - **B 站**：`BV号`、`av号`、`bilibili.com/video/...`、`b23.tv` 及 `bili2233.cn` 等镜像短链，支持 `?p=2` 分P参数
  - **小红书**：`xhslink.cn` / `xhslink.com` 短链、`explore` / `discovery/item` 完整链接、"复制文字打开小红书"那种带口令的分享文本
  - **抖音**：`v.douyin.com` 短链、`douyin.com/video/...`、带口令的分享文本
  - **QQ 小程序分享的卡片**同样能识别（那种消息里链接藏在卡片里，不在文本里）
- 📋 **视频解析**：标题、UP 主、时长、播放量、分P信息，数据来自 B 站公开接口（**无需登录、无需 Cookie**）
- 🧠 **AI 总结**：调用当前会话的大模型生成 3~5 句总结，并在卡片上**注明总结依据**；提示词要求模型尽力推断而不是摆烂，且不编造未提供的信息
- 📜 **字幕增强（可选）**：填入 `sessdata` 后用视频字幕做总结，能讲清「视频里讲了什么」；无字幕或凭据失效时自动回退，不影响其它功能
- ⬇️ **按需下载**：默认只发解析 + 总结；回复「下载」或发送 `/bdl` 才下载视频文件（也可以在面板打开「自动发送视频文件」）
- 🔀 **两种发送方式**：本地文件 / 直链 URL，`auto` 模式下本地文件发送失败会**自动改用直链**，兼容协议端与 AstrBot 分离部署（Docker）的环境
- 🪜 **四级降级**：直链接口 → 表单页 → 解析页 → 回复网页链接，下载站抽风也不会「已读不回」
- 🛡️ **多重防刷屏**：**按用户**的触发冷却 + **按视频**的重复判定（同一视频默认 10 分钟内只处理一次，**不同用户发同一链接也算重复**）、群白名单、触发范围限定、会话级开关
- 💤 **不插话**：群里 `@` 别人的消息里带链接时不响应（用 @ 机器人或直接发链接即可正常解析）
- 💬 **热门评论单独成图**：版式对齐 B 站评论区——顶部信息区（分辨率 / 类型 / 评论数 / 时长）+ **视频二维码**，圆形头像、等级小方块徽章、`UP` 标签、粉丝勋章与装扮编号，含发布时间、回复数、点赞数与**评论附图**（保持原比例、不裁切）；条数可配
- 📦 **合并转发**：本次解析的消息条数达到阈值时打包成一条转发消息（**含视频**），防刷屏；填 `0` 可关闭
- 📊 **可自查**：管理员用 `/bdlstatus` 一屏看到解析与下载计数、卡片状态、缓存命中、下载站三条路径近况
- ⚡ **接口缓存**：视频信息与热评缓存 5 分钟且跨会话共享，同一个视频被多个群先后发出时不重复请求 B 站
- 📉 **体积保护**：下载前用 `HEAD` 预检体积，超限直接改发链接，不会先下几百 MB 再放弃
- 🧹 **自动清理**：临时文件在发送完成后删除，另有 24 小时残留兜底清理

## 🚀 使用方法

| 操作 | 效果 |
|------|------|
| 发送链接（B 站 / 小红书 / 抖音） | 先给消息**贴个表情**表示「开始解析」，再回复图片卡片（B 站开启「自动发送视频文件」时同时发视频；图文笔记会把图一起发） |
| 回复「下载」 | 下载本会话最近解析过的**视频**（30 分钟内有效；图文笔记不用这一步，图会在解析时直接发） |
| `/bdl` | 同上，下载最近解析过的视频 |
| `/bdl <链接或BV号>` | 直接解析并下载指定视频 |

以上为普通用户可用。**管理员**另有 4 个命令：

| 命令 | 作用 |
| --- | --- |
| `/bdlstatus`（`/bdl状态`） | 查看运行状态：版本、运行时长、解析与下载计数、模型、卡片状态、缓存命中、下载站三条路径近况、最近一次错误 |
| `/bdlclear`（`/bdl清缓存`） | 清空视频信息与热评缓存 |
| `/bdloff`（`/bdl关`） | **本会话**关闭自动解析（只想安静聊天时用，不影响其它群） |
| `/bdlon`（`/bdl开`） | 恢复本会话的自动解析 |

> 🎭 收到链接后默认给原消息**贴一个表情**表示「已开始解析」（不再发「正在解析」的文字），少一条消息、不刷屏；仅在 QQ 生效，协议端不支持表情回应时会自动回退为文字。表情 ID 可在面板调整（`react_emoji_id`），填 `0` 则始终用文字。
> 💡 AstrBot 默认命令前缀为 `/`，如果你改过前缀，`/bdl` 也要相应调整。
> 「下载」关键词只在**本会话刚解析过视频**时才响应，其他时候会正常交给 LLM 对话，不会抢话。
> 「本会话关闭自动解析」只影响自动响应链接；`/bdl` 等显式命令仍然可用，插件重启后恢复为开启。

## ⚙️ 配置项

在 AstrBot WebUI → 插件配置面板中可调：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `trigger_scope` | 下拉 | `group` | 触发范围：仅群聊 / 仅私聊 / 两者 |
| `need_at_in_group` | 开关 | `false` | 群聊中是否必须 @机器人 才自动解析，防群里刷屏 |
| `enabled_platforms` | 列表 | `["bilibili","douyin","xiaohongshu"]` | 启用的解析平台：`bilibili` / `douyin` / `xiaohongshu`；**留空表示全部启用**，书写顺序决定同一段文本先问哪个平台 |
| `react_emoji_id` | 整数 | `289` | 收到链接时贴的表情 ID（仅 QQ）；填 `0` 则改回文字提示 |
| `send_video` | 开关 | `false` | **是否自动发送视频文件**；关闭时靠「下载」/`/bdl` 按需触发 |
| `video_send_mode` | 下拉 | `auto` | 视频发送方式：自动（失败降级直链）/ 仅本地文件 / 仅直链 URL |
| `max_video_mb` | 整数 | `40` | 视频体积上限（MB），超限不发文件、改发链接。实测协议端上传群视频在 **41MB** 处稳定失败（`Highway code 102902`），所以默认压到 40；**不建议调大** |
| `enable_summary` | 开关 | `true` | 是否启用 AI 总结；未配置大模型时自动跳过 |
| `summary_max_chars` | 整数 | `400` | AI 总结字数上限，超出截断；调到 200 以下容易把话说一半 |
| `summary_timeout` | 整数 | `45` | AI 总结超时（秒），超时跳过总结，避免群里长时间无响应 |
| `reply_limit` | 整数 | `10` | 取多少条热门评论作为**给 AI 的**总结参考；填 `0` 则只依据标题与简介 |
| `show_replies` | 开关 | `true` | 把热门评论**单独渲染成一张图片**发送（头像 / 昵称 / 等级 / 点赞数） |
| `replies_show_count` | 整数 | `5` | 热评图片里展示几条；建议 3~6，太多图片会很长 |
| `sessdata` | 文本 | （空） | **可选**。填入 B 站 SESSDATA 后可用视频字幕做总结（质量显著提升）；留空则完全不需要登录 |
| `prefer_subtitle` | 开关 | `true` | 填入 SESSDATA 后是否优先用字幕总结；无字幕时自动回退 |
| `subtitle_max_chars` | 整数 | `6000` | 送入模型的字幕上限，避免长视频显著增加调用费用 |
| `request_timeout` | 整数 | `20` | 网络请求超时（秒），下载站偶尔响应慢，建议不低于 15 |
| `max_concurrent` | 整数 | `1` | 同时进行的下载任务数，建议 1~2 |
| `user_cooldown` | 整数 | `60` | **单用户**两次触发的最小间隔（秒），防刷屏；填 `0` 关闭 |
| `duplicate_window_minutes` | 整数 | `10` | **同一个视频**多少分钟内只处理一次；不同用户发同一链接也算重复；填 `0` 关闭 |
| `group_whitelist` | 列表 | `[]` | 群白名单，留空表示所有群生效 |
| `send_ebilibili_link` | 开关 | `true` | 回复中是否附上 ebilibili 网页下载链接 |
| `forward_threshold` | 整数 | `3` | 本次解析的消息条数达到该值时**合并成一条转发**（**含视频**）；填 `0` 关闭，此时**卡片先出**（解析完立刻发卡片，再下载视频） |
| `forward_sender_name` | 文本 | `B站视频解析` | 合并转发里显示的发送者名称 |
| `output_image` | 开关 | `true` | 以图片卡片回复解析结果；关闭或渲染失败时退回纯文本 |
| `card_width` | 整数 | `760` | 卡片最大宽度（像素），推荐 700~800；过宽会被 QQ 缩小显示，代码内限制 560~1000 |
| `history_keep` | 整数 | `50` | 面板「最近」页保留多少条解析记录；填 `0` 不记录 |
| `card_qrcode` | 开关 | `true` | 热评图右上角画视频链接的二维码（**本地生成、不联网、不引依赖**）；不需要可关掉 |
| `verbose_log` | 开关 | `false` | 详细日志：输出降级原因、下载进度、耗时，排查问题时开启 |

> 🎛️ **平台专属项不在上面这张表里**（比如「图集最多发送张数」「自动发送图集」「抖音第三方接口」「小红书 Cookie」）。这些在**面板对应的平台页**里改，写进 `runtime.json` 覆盖层，改完即时生效、不用重启，也不污染 AstrBot 的配置文件。

## 🧠 AI 总结说明

总结由 AstrBot **当前会话使用的对话模型**生成，因此需要先在 AstrBot 里配置好模型（未配置或调用失败时会自动跳过，不影响解析与下载）。

**它只读文字、不读图。** 小红书 / 抖音的图文笔记，模型看到的是标题、正文和话题标签，**图片内容它看不到**——正文写得少就只能靠标签推断（比如正文只有一句「本来躺得好好的」，模型是靠 `#自动续费#` 这个标签猜出梗的）。卡片上会如实标注依据，不假装「看过」。

各平台能喂给模型的东西不一样：

| 平台 / 情况 | 送给模型的输入 | 卡片上的依据标注 |
|------|------|------|
| B 站（未登录） | 标题 + UP主 + 时长 + 分区 + 标签 + 分P名 + 简介 + 播放/点赞数 + 热评 Top N | 基于简介与热评 |
| B 站（有字幕） | 上面的 + **字幕全文** | 基于字幕 |
| 小红书 / 抖音图文 | 标题 + 正文 + 话题标签 | 基于标题与简介 |

**B 站的字幕是「能说出视频内容」的关键**：元数据与热评只能推断「这是什么视频」，只有字幕才能讲清「视频里讲了什么」。

花费多少 token、哪些环节不花，见下方 FAQ「哪些地方会消耗 AI 的 token」。

### 怎么开启字幕总结

1. 浏览器登录 B 站（**建议用小号**），从 Cookie 里复制 `SESSDATA` 的值；
2. 粘贴到面板的「B站 SESSDATA」配置项（输入框是密码样式）；
3. `prefer_subtitle` 保持开启即可。

> ⚠️ `SESSDATA` 是账号登录凭据。插件只用它读取字幕接口，**不涉及点赞 / 关注 / 投币等任何账号操作**，日志与 `/bdlstatus` 输出中也不会出现它的值。
> 不填时，插件的行为与「完全不需要登录」的版本**一模一样**。
> 💡 无字幕的视频、或凭据失效时，会自动回退到 L1/L2 并如实标注依据，不报错、不空回复。

## 📦 媒体从哪里下载

**B 站视频**依赖第三方站点 [ebilibili.com](https://www.ebilibili.com/download)（把 `bilibili.com` 改成 `ebilibili.com` 即可下载对应视频的那个站）。插件按以下顺序尝试，前一步失败自动进入下一步：

| 顺序 | 方式 | 说明 |
|:---:|------|------|
| 1 | `GET /api/playurl/{bvid}/{cid}` | 直链接口，返回 B 站 CDN（`bilivideo.com`）的 MP4 直链 |
| 2 | `POST /download`（表单 `bvid`） | 从返回 HTML 中提取 `startDownload(...)` 的直链 |
| 3 | `POST /downloads`（表单 `url`） | 新解析页，支持 B站/抖音/快手/小红书 |
| 4 | 回复网页链接 | 以上全失败时，回复 `https://www.ebilibili.com/video/{bvid}` 让用户自行下载 |

注意事项：

- 直链带有效期（`deadline` 参数），插件拿到后会立即下载，不会缓存复用
- 该站是**个人小站、无可用性保证**，接口可能随时变更；插件对网络抖动做了重试与退避，但仍可能失败，此时会明确提示而不是静默失败
- 直链来自 B 站 CDN，下载时须带浏览器 UA（B 站 CDN 会对非浏览器 UA 返回 403），插件已统一处理

**小红书 / 抖音不需要第三方站**：分享页里就带着直链，插件直接取 CDN 地址——

- 小红书图集走 `fileId` 直连原图 CDN，拿到的是**无水印原图**；取不到时退回页面给的签名地址（带水印，但至少能出图）
- 抖音图集优先挑不带 `~tplv-dy-watermark` 的变体，并清掉 `watermark` 参数
- 图文笔记一律**先下载到本地再发**：直接把 URL 交给 QQ 时它要自己回源拉图，遇防盗链或慢 CDN 就是裂图
- 小红书视频取 `video.media.stream` 里兼容性最好的 h264 流

## 🔧 技术特点

- **被动正则匹配**：`@filter.regex(...)` 识别链接，无需唤醒词；认不出的消息完全不响应
- **平台抽象层**：`MediaRef`（匹配结果）→ `parse()` → `MediaInfo`（统一媒体模型）→ `resolve_media()`（取直链）。**新增一个平台只要写一个文件**，卡片渲染 / AI 总结 / 发送编排 / 面板全都不用改
- **能力位驱动**：平台用 `CAP_VIDEO` / `CAP_IMAGES` / `CAP_SUMMARY` 声明自己有什么，上层据此决定发视频还是发图集，不必到处写 `if platform == ...`
- **零依赖图片卡片**：复用 AstrBot 内置文转图（`html_render` / `text_to_image`），不引入 Pillow / wkhtml / 内建字体；封面与头像下载后以内嵌 data URI 传入，规避 B 站图片 CDN 的 UA/Referer 校验；连续渲染失败 2 次后本进程内自动改回纯文本，不让渲染拖慢回复
- **纯异步**：`aiohttp` + `asyncio`，下载流式写盘，不阻塞事件循环
- **发送后清理**：所有发送 `await` 完成后才删除临时文件——早期版本在生成器 `finally` 中删除，会在 AstrBot 真正发送前把文件删掉，导致协议端报 `retcode 1200 路径不存在`（详细分析见 CHANGELOG 的 v0.1.1）
- **发送方式自愈**：本地文件发送失败时自动改用直链，适配协议端与 AstrBot 不在同一文件系统的部署
- **文本与视频分开发送**：避免「长文本 + 视频」的混合消息链被包装成合并转发，规避各协议端对转发消息中视频段的兼容差异
- **体积预检**：`HEAD` 拿到 `Content-Length` 即判断，超限不落盘
- **状态防抖**：用户冷却、同链接处理中标记（带时间戳自动过期，不会永久卡死）；去重 key 按「视频标识 + 分P」归一化，同一视频的三种链接写法只处理一次
- **可诊断**：`/bdlstatus` 汇总解析与下载计数、缓存命中率、下载站三条路径近况；只读、不调 LLM、不输出任何凭据
- **错误隔离**：解析失败、总结失败、下载失败、发送失败都被隔离处理，单条消息出错不影响插件整体

## ❓ FAQ

**Q：为什么只发了文字，没有视频文件？**

A：默认不自动发视频（避免流量消耗与平台风控）。可以在面板打开「自动发送视频文件」，或回复「下载」、发送 `/bdl` 按需获取。

**Q：日志报 `retcode 1200`「路径不存在」，视频发不出去？**

A：协议端（NapCat / LLOneBot 等）读不到 AstrBot 本地的文件，常见于协议端与 AstrBot 分处不同容器/主机（Docker 分离部署）。插件默认的「自动」模式会在本地文件发送失败后自动改用直链；也可以直接把「视频发送方式」设为**仅直链 URL**，此时插件完全不落盘，把 ebilibili 直链交给协议端自己拉取，省磁盘也省中转流量。

**Q：日志报 `HTTP 412` 或「B 站风控拦截（HTTP 412）」？**

这是 **B 站的风控拦截**，不是插件参数错误。常见原因：

- **服务器 IP 被判定为脚本访问**（云主机比家庭宽带更容易命中）；
- 短时间内请求过多（多个群同时发链接、反复触发解析）；
- 请求里缺少浏览器必带的 cookie。

按顺序处理：

1. **稍等几分钟再试**——B 站的 412 多为短时封控；
2. 插件已自动带上 `buvid3`（B 站下发的设备指纹 cookie，**无需配置**），通常能缓解；
3. 仍然频繁 412 时，在面板填入 **`SESSDATA`**（见上方「字幕增强」）——登录态请求的风控阈值明显更宽；
4. 降低压力：`max_concurrent` 保持 `1`，`user_cooldown` 调大一些。

**Q：日志报 `[Highway] httpUpload ... code 102902`，群里只收到一句提示？**

这是**协议端上传到 QQ 失败**，不是插件下载失败。协议端日志里会先出现「视频信息 / 开始生成视频缩略图」，然后才报 `Highway` 分块上传错误。

- 常见于**视频偏大**（实测 51.9MB 会出现）或**网络中断**；
- 插件会补发一条带 ebilibili 链接的提示，点开即可自行下载；
- 想减少这种情况：把「视频体积上限 (MB)」调小（例如 40），超过就只发链接、不尝试发文件。

**Q：提示「视频约 N MB，超过体积上限」？**

A：这是**保护性拦截**，不是故障。实测协议端上传群视频在 **41MB（42991616 字节）** 处会稳定失败（`Highway ... code 102902`，51.9MB 与 54.3MB 两个视频都卡在同一点），所以上限默认是 40MB。

**不建议调大** —— 调大只会让它先花几十秒下载、再花一两分钟上传失败。需要原视频时点回复里的 ebilibili 链接自行下载。

**Q：一直提示下载失败？**

A：说明 ebilibili 四条路径都没走通（站点限速、接口变更或网络受限）。可稍后重试、直接访问回复里的网页链接，或打开「详细日志」看具体是哪一步失败。这类第三方站点无法保证长期可用，插件已尽力降级。

**Q：图片卡片发不出来 / 一直是纯文本？**

A：卡片依赖 AstrBot 的**文转图服务**。未配置或渲染失败时插件会自动退回纯文本，功能不受影响（日志里会有 `卡片渲染连续失败 N 次` 的 warning）。可检查 AstrBot 的文转图配置，或把「以图片卡片回复」关掉以跳过渲染。卡片里的封面与 UP 主头像取不到时会显示灰底占位块，不影响其余内容。

**Q：哪些地方会消耗 AI 的 token？会不会额外收费？**

A：分两块看——**渲染永远不花 token，只有「AI 总结」那一句话会花**，而且走的是 AstrBot 里**你自己配置的模型**，按那个模型的价格计费，插件本身不内置模型、不额外加价。

先说不花钱的：渲染走 AstrBot 的文转图服务（容器内 Playwright 截图），全程没有 LLM 参与：

| 环节 | 消耗 |
| --- | --- |
| 信息卡片、热评图渲染 | **0 token**（只吃 CPU / 内存） |
| 封面、头像、评论头像、评论附图的内嵌 | **0 token**（站方图片 CDN 的普通 HTTP 请求） |
| 图集 / 视频下载与发送 | **0 token**（纯 HTTP 下载 + 协议端上传） |
| 合并转发、贴表情 | **0 token**（QQ 协议端 API） |
| `replies_show_count`（热评展示条数） | **0 token** ← 调大调小与费用完全无关 |

**唯一花 token 的是那次 AI 总结调用**。不同平台送进模型的东西不一样，量级也不同（2026-11-02 实测）：

| 平台 / 情况 | 送给模型的内容 | 单次消耗 |
| --- | --- | --- |
| 小红书图文、抖音 | 标题 + 正文 + 话题标签（没有字幕、没有热评） | **约 700~800 token** |
| B 站（未登录，无字幕） | 标题 / UP主 / 分区 / 标签 / 分P / 简介 + 10 条热评 | **约 1k token** |
| B 站（已登录 + 有字幕） | 上面这些 + 字幕全文（受 `subtitle_max_chars` 限制） | **约 3k token** |

输入由这三个配置决定：

| 配置 | 默认 | 对 token 的影响 |
| --- | --- | --- |
| `subtitle_max_chars` | `6000` | **最大的一项**：填了 `sessdata` 且有字幕时，字幕全文会送进模型 |
| `reply_limit` | `10` | 送给 AI 的热评条数（每条最长 100 字） |
| `summary_max_chars` | `400` | 输出长度上限 |

绝对量很小，想省就把 `subtitle_max_chars` 或 `reply_limit` 调小；完全不想要总结就把「启用 AI 总结」关掉（`enable_summary`），改由纯解析 + 卡片回复，**0 token**。

> 💡 面板「试解析」里勾选「同时生成 AI 总结」也会**真调一次模型**（同样几百 token）。只想确认链接能不能解析，把那个勾去掉再点。
>
> 💡 想统计自己实际花了多少，看 AstrBot 的模型用量统计，或换成自建 / 本地模型（如 Ollama），那部分就是 0 成本。

> ⚠️ 注意区分两个「热评条数」：`reply_limit` 是**给 AI 看的**（花 token），`replies_show_count` 是**画在图片里的**（不花 token）。想让卡片更好看，放心调后者。

**Q：热评图右上角的二维码是什么？扫不出来怎么办？**

内容是视频链接（有分P也会带上），扫码可直接在 B 站打开该视频。

- 由插件**本地生成**（纯标准库实现，**不联网、不调用任何第三方服务**），所以不存在把链接发给第三方的问题；
- 不想显示：把「热评图带视频二维码」关掉即可，卡片其余部分不受影响；
- 扫码没反应或显示异常：同样建议先关掉。这个二维码是本插件自行实现的（没有引入二维码库），**尚未在真机核对扫码结果**，关掉后一切照旧。

**Q：AI 总结不够具体 / 读起来不流畅？**

A：分几种情况：

- **读起来像在「交代线索」**（满篇「视频看起来…」「热门评论在玩…」）：那是旧版提示词的问题，现已修正——新版要求直接叙述内容、**禁止元话语、禁止总结评论区**，并给了句式风格示例。更新到最新版并重新解析即可。
- **话没说完就被截断**：`summary_max_chars` 设得太小。默认已调为 400 字，如果你之前手动改小过，把它改回来。
- **没配 `sessdata`**：B 站字幕接口需要登录态，此时总结只能基于标题、UP主、分区、标签、分P名、简介与热门评论——它说得清「这是什么视频」，但说不出「视频里讲了什么」。想解决就填入 `sessdata`（见上方「AI 总结说明」）。
- **配了 `sessdata` 但仍不具体**：说明这个视频没有可用字幕（生肉、纯音乐、或 UP 主关闭了字幕），插件已自动回退到元数据总结并在卡片上标注了依据。

**Q：会消耗很多流量或磁盘吗？**

A：默认模式（不自动发视频）只做解析和文本总结，流量极小。下载视频时才产生流量，且临时文件在发送后立即删除。「仅直链 URL」模式下机器人完全不下载视频，流量由协议端承担。

**Q：私聊可以用吗？**

A：可以，把「触发范围」改为「群聊和私聊」或「仅私聊」即可。

**Q：分P视频下载的是哪一P？**

A：链接里带 `?p=2` 就下载第 2P，卡片上会标注「（P2）」；不带 `p` 参数则下载第 1P。`p` 超出范围时按第 1P 处理。

**Q：某个群刷屏太厉害，能单独关掉吗？**

A：可以。管理员在该群发送 `/bdloff`（或 `/bdl关`）即关闭**该会话**的自动解析，其它群不受影响，`/bdl` 等显式命令也仍然可用；发送 `/bdlon` 恢复。这个开关只存在内存里，插件重启后自动恢复为开启，不会写进配置。

**Q：怎么确认插件在正常工作？**

A：管理员发送 `/bdlstatus` 可以看到版本、运行时长、解析与下载计数、当前会话模型、卡片渲染状态、缓存命中次数，以及下载站三条路径最近一次的结果与最近一次错误原因。

**Q：为什么机器人的回复被合并成一条转发了？**

A：有两处会做合并转发，各管一段，都值得知道：

- **插件配置的「转发阈值」**（`forward_threshold`，默认 3）：本次解析产生的消息条数达到该值，插件主动把它们打包成一条转发（**视频也会一起打包**）。想保持逐条发送就把它设为 `0`。
- **AstrBot 平台设置里的 `forward_threshold`**：这是 AstrBot **自带**的功能，作用于机器人发出的所有消息，与插件配置无关。两者不会互相破坏（插件已经发出转发时，AstrBot 会跳过二次包装），但如果发现消息被意外合并，两处都要看一眼。

> 合并转发**仅在 QQ 群聊生效**（OneBot v11 的限制）；私聊与其它平台会自动退回逐条发送。
> 由于视频要一起打包，触发合并转发时**必须等视频下载完成**才能发出——此时「卡片先出」不再成立；把阈值设为 `0` 可以恢复逐条发送（卡片先出）。

**Q：会不会导致 B 站封号？**

A：插件只调用**公开且无需登录**的接口（视频信息、热门评论），不登录、不携带任何 Cookie、不涉及账号操作；同时对下载做了并发限制与冷却。请勿修改代码进行高频抓取。

**Q：小红书 / 抖音为什么没有扫码登录？**

A：这两家的二维码接口都已封禁，实测结果：小红书 `api/sns/web/v1/login/qrcode/create` 直接返回 `500 create invoker failed`（网关层要求 JS 生成的 `x-s` 签名）；抖音 `sso.douyin.com/passport/web/get_qrcode` 返回 `403 路由已封禁`，主站只回一个 2.4KB 的风控挑战页、一个 Cookie 都不下发。所以只有 B 站支持扫码，另外两家请用「贴 Cookie」（现在会告诉你登的是谁）或「第三方接口」。

**Q：抖音为什么有时候能解析、有时候提示「要求签名校验」？**

A：抖音没有公开接口，插件走的是分享页 SSR 里内嵌的数据。这份数据**不是每次都下发**——同一台机器、同一分钟，可能一次拿到完整的标题/作者/封面/直链，下一次就只剩一个空壳页面（这也是为什么它是"时好时坏"而不是"完全不能用"）。取到数据就直接解析，取不到才降级：先在面板「平台」页填一个第三方解析接口地址，没填就回一句人话提示。小红书和 B 站不受影响。

**Q：图文笔记的图只能发 5 张？**

A：默认只发**前 5 张**，并在末尾补一句「这组共 N 张，先发了前 5 张」。图文作品动辄二三十张，一次发太多既刷屏又容易被 QQ 限流。

想多发就在**面板 → 对应平台页 → 图集最多发送**里改（1~35 张），改完即时生效、不用重启；不想要图集就把「自动发送图集」关掉，只发卡片。

**Q：小红书链接明明是对的，却提示「没拿到笔记内容」？**

A：按这几种情况排查：

- **需要登录才能看的笔记**（比如部分收藏夹内容）：在面板「小红书」页贴一份浏览器 Cookie，点「测试」会直接告诉你**登的是谁**
- **触发了风控**：会明确报「返回了验证页」，等几分钟再试，换一条链接也不一定有用——这是 IP 维度的事
- **笔记已删 / 私密**：确实拿不到，插件会如实说「没拿到笔记内容」，不会假装成功
- **分享文本被截断**：短链 `xhslink.cn/o/xxxx` 后面那串大小写字母要完整，缺字符会跳到错误页面
